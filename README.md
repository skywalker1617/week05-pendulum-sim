## 人机协同三反思

### 1. 意图清晰度反思

第一轮让 AI 生成 MVP 时，我最初只写了“做一个单摆模拟器，要好看”，结果 AI 给出的版本摆动很快、且没有说明用的什么积分方法——问题出在我的提示词**缺少“约束”和“验收标准”两段**，AI 只能自己猜测摆长、初始角度和精度要求。后来我补齐了四段式结构：明确“【约束】初始参数 L=200px、g=9.8、初始摆角 45°，纯 Canvas 不引外部库”，并加上“【验收标准】双击打开即可流畅左右摆动、控制台 0 报错”。补齐后首轮产出即通过验收，说明**验收标准写清楚，AI 的首轮正确率会显著提高**。

### 2. 闭环控制反思

排错时我没有用“怎么坏了，帮我重写”这种情绪化反馈，而是按 F12 打开控制台，复现“点击重置按钮”的现场后复制完整的红色堆栈 `Uncaught ReferenceError: resetAnimation is not defined` 作为证据喂给 AI。AI 的 Reflection 定位到根因：事件绑定引用的函数不在当前作用域（函数定义位置/作用域链问题），修复方式是把处理函数与按钮绑定收敛到同一作用域并保持引用一致。我完全看懂了这个修复——它不是改物理公式，而是修**边界条件（作用域与事件绑定）**；物理部分 α = -(g/L)·sinθ - k·ω 的离散化我逐行核对过：先更新 ω 再更新 θ 的半隐式欧拉格式保证了能量不发散，这与我观察到的“长时间摆动振幅衰减平滑、无数值爆炸”相互印证。

### 3. 主体地位确认

由我（产品总设计师）决定的核心决策：**物理模型的换算方案**（像素域与米制域的比例 PX_PER_METER=60，决定周期读数是否真实）；**验收口径**（控制台 0 报错、45° 精准复位、滑块范围按指导书定义）；**交互取舍**（在指导书要求之外追加暂停按钮与 θ/ω/T 实时读数，因为这直接影响“可观测性”）；以及对 AI 每轮产出的**质量裁判**（用无头浏览器实测摆动、拖滑块、点重置后才允许 commit）。由 AI 完成的重复劳动：HTML/CSS 布局与发光光效等纯语法实现、事件监听样板代码、Canvas 渐变绘制的具体写法，以及按 ReAct 证据执行的外科手术式修复。我的时间花在“提需求、设边界、看效果、给反馈”上，这正是 HOTL 模式的价值所在。
